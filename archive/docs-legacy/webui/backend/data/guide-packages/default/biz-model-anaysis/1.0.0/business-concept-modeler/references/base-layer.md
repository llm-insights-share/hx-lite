# 基础抽取层（Base Layer）

适用于所有领域的通用抽取规则。每次执行均必须加载此文件。

---

## 一、实体识别规则

### 1.1 判定为实体的条件（满足≥2条）
- 文档中有唯一标识符（编号、ID、名称）
- 文档中描述了它的多个属性
- 它参与了至少一个业务流程动作
- 它有明确的创建者/负责人
- 它在多个段落/章节中反复出现

### 1.2 实体分级判定

| 级别 | 判定条件 |
|------|---------|
| 核心实体 | 独立生命周期 + 出现在≥2个业务流程 + 有唯一标识 |
| 从属实体 | 必须依附某核心实体存在 + 自身有属性 |
| 值对象 | 无唯一标识 + 仅为描述性信息 + 不参与流程动作 |
| 角色/参与方 | 执行业务动作的主语 + 无需管理其生命周期 |

### 1.3 常见实体类型参考（不限于）

```
单据类：申请、订单、合同、报告、通知、审批单、结算单
对象类：项目、产品、资产、账户、档案
主体类：企业、部门、供应商、客户、员工
事件类：会议、验收、审计、检查
```

### 1.4 排除噪音
以下不应成为实体：
- 纯描述性的形容词短语
- 流程中的"步骤"本身（除非它有独立属性）
- 在全文仅出现1次且无属性描述的名词

## 二、关系抽取规则

### 2.1 关系识别语言模式

| 语言模式 | 关系类型示例 |
|---------|------------|
| "A 包含 B" / "A 由 B 组成" | A 1:N B |
| "A 对应 B" / "A 关联 B" | A 1:1 B 或 A 1:N B |
| "A 发起/申请/提交 B" | A → B（触发关系） |
| "A 属于 B" / "B 下的 A" | B 1:N A |
| "多个A共用一个B" | A N:1 B |
| "A 和 B 均参与 C" | A M:N B（通过C） |

### 2.2 基数标注规则
- 1:1：文中出现"唯一对应"、"专属"
- 1:N：文中出现"一个...可以有多个"、"每个...下有若干"
- M:N：两个实体可相互关联多个，通常需要关联实体

### 2.3 关系命名规范
- 使用业务动词而非技术词汇
- 正确：`发起`、`归属于`、`包含`、`审批`
- 错误：`hasMany`、`belongsTo`、`FK`

## 三、属性归类规则

### 3.1 属性分类

| 类型 | 描述 | 举例 |
|------|------|------|
| 标识属性 | 唯一标识实体 | 编号、ID、名称 |
| 描述属性 | 说明实体特征 | 类型、规格、说明 |
| 状态属性 | 反映生命周期 | 状态、阶段、审批结果 |
| 时间属性 | 记录时间节点 | 创建时间、截止日期 |
| 金额属性 | 货币相关 | 金额、预算、结算价 |
| 关联属性 | 外键/引用 | 合同编号、项目ID |

### 3.2 属性提取信号
- 表格的列名 → 直接对应属性
- "XX的XX"结构 → 前者是实体，后者是属性
- 填写要求说明 → 通常是必填属性
- 审核/校验条件中的字段名 → 关键属性

## 四、状态机识别规则

### 4.1 状态机存在信号
出现以下任意信号，说明该实体有状态机：
- 文中有"状态"、"阶段"、"环节"字段描述
- 文中有流程图、审批流
- 文中描述了"从A到B"的变化过程
- 文中有"待XXX"、"已XXX"、"XXX中"的状态词

### 4.2 状态转换提取
每个转换需提取：
- 起始状态
- 目标状态
- 触发条件（事件/动作）
- 执行角色（谁触发）

### 4.3 标准状态模式参考

```
草稿 → 提交 → 审批中 → 通过/拒绝 → 执行中 → 完成/终止
```

## 五、业务规则提取规则

### 5.1 规则识别关键词
```
强制性：必须、应当、须、不得、禁止、不允许
条件性：当...时、如果...则、超过...应
数值性：不超过、至少、最多、不少于
时限性：在...内、不得超过X天、到期前
```

### 5.2 规则结构化格式
```
规则编号：BR-[序号]
规则类型：[约束/触发/计算/校验]
描述：[业务语言描述]
涉及实体：[相关实体名称]
原文出处：[段落或条款编号]
```

### 5.3 规则分类
- **约束规则**：禁止或限制某种状态/行为
- **触发规则**：当某条件满足时触发某动作
- **计算规则**：金额、数量的计算逻辑
- **校验规则**：数据完整性要求
