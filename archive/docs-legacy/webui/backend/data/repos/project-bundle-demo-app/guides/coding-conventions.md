# 编码规范（coding-conventions）

## 目的
统一应用软件交付中的代码风格、分层、命名与可维护性约定，降低协作与评审成本。

## 适用场景
- 开发实现（apply）与变更编码阶段
- 代码评审、重构与结对时作为约束依据

## 工作步骤
1. 确认项目技术栈与既有规范（lint/format/目录约定）
2. 按分层边界编写：接口层、领域/应用层、基础设施层职责清晰
3. 命名与模块拆分遵循可读性优先；公共能力复用，禁止复制粘贴式扩散
4. 补充必要注释与错误处理；敏感信息不入仓
5. 提交前跑通格式化与静态检查

## 产出物
- 符合规范的代码变更
- 必要时更新项目内约定文档

## 约束
- 不跨越模块边界直接访问他层私有实现
- 不以「赶工」绕过类型检查与基础测试

## 完成标准
- 变更可通过 lint/typecheck
- 关键路径有可理解命名与错误信息
- 无明文密钥与调试残留
