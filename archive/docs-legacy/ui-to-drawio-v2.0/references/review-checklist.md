# 原型图 Review 修订检查清单

生成初版 drawio 并完成重叠检测、PNG 导出后，**必须**执行本 Review 环节，再交付给用户。

---

## 第六步 通道一：XML 自检（先于需求审查）

读回 `.drawio` 文件，逐区域扫描以下维度。自检目标是**发现生成阶段的坐标/样式错误**，降低后续返工。

### A. 对齐检查

| 检查项 | 检查方法 | 常见问题 | 阈值 |
|--------|---------|---------|------|
| 表单标签左对齐 | 同一卡片内所有 `<mxCell id="txt_*">` 的 `x` 坐标一致 | 标签 x 参差（部分 248、部分 260） | 偏差 > 4px |
| 输入框左对齐 | 同一卡片内所有 `<mxCell id="inp_*">` 的 `x` 坐标一致 | 输入框 x 不一致 | 偏差 > 4px |
| 按钮右对齐 | 按钮组内 `x + w` 值一致（右贴卡片边界） | 按钮右边界不齐 | 偏差 > 4px |
| 统计卡片上对齐 | 同一行统计卡片的 `y` 坐标一致 | 卡片高低错落 | 偏差 > 2px |

**自检操作**：
1. 用 grep/搜索提取所有组件 `mxGeometry` 的 `x`、`y` 值
2. 按组件前缀 (`txt_`/`inp_`/`btn_`/`stat_`) 分组
3. 检查组内同方向坐标是否一致
4. 不一致的 → 记录到修订清单，取多数值或最大值作为修正目标

### B. 间距检查

| 检查项 | 期望间距 | 检查方法 |
|--------|---------|---------|
| 组件垂直间距 | 16px | 相邻组件 `y[n+1] - (y[n] + h[n])` = 16 |
| 统计卡片水平间距 | 16px | 相邻卡片 `x[n+1] - (x[n] + w[n])` = 16 |
| 标签与输入框间距 | 8px | `inputX - (labelX + labelW)` = 8 |
| 按钮组内间距 | 8px | 相邻按钮 `x[n+1] - (x[n] + w[n])` = 8 |
| 卡片内边距（左右） | 24px | 组件 `x - cardX` ≥ 24 且 `(cardX + cardW) - (x + w)` ≥ 24 |

**自检操作**：
1. 按区域（同一卡片内）提取所有组件坐标
2. 按 `y` 排序后计算相邻差值
3. 差值 ≠ 期望值的 → 记录，以下方组件 `y` 坐标调整为修正方案

### C. 字号层级检查

| 元素类型 | 期望字号 | 期望字重 | 检查要点 |
|---------|---------|---------|---------|
| 页面标题/Logo 文字 | 16px+ | bold (`fontStyle=1`) | 是否为页面最大字号 |
| 卡片标题 | 14px | bold (`fontStyle=1`) | 是否小于页面标题 |
| 统计数值 | 24px | bold | 是否为卡片内最大字号 |
| 统计标签/辅助文字 | 12px | normal | 是否小于统计数值 |
| 正文/按钮/表格 | 12-13px | normal | 是否一致 |
| 面包屑/页脚/分页 | 12px | normal | — |

**常见违规**：卡片标题 12px 与正文同号 → 修正为 14px bold；统计标签 14px 大于数值 → 修正为 12px。

### D. 颜色检查

按 SKILL.md 2.4 颜色参考表逐一核对：

| 检查项 | 正确颜色 | 常见错误 |
|--------|---------|---------|
| 侧边栏背景 | `#001529` | 误用 `#002140` 或其他深蓝 |
| 侧边栏选中项 | `#1890FF` | 误用 `#0050B3` |
| 页面背景 | `#F0F2F5` | 误用 `#F5F5F5` 或纯白 |
| 主色按钮 fill/stroke | 均为 `#1890FF` | fill 和 stroke 颜色不一致 |
| 次色按钮 stroke | `#D9D9D9` | 误用 `#BFBFBF` |
| 输入框 stroke | `#D9D9D9` | 误用 `#F0F0F0` |
| 表格表头 fill | `#FAFAFA` | 误用 `#F5F5F5` |
| 成功标签 fill | `#F6FFED` / stroke `#B7EB8F` | 颜色不匹配语义 |
| 失败标签 fill | `#FFF1F0` / stroke `#FFA39E` | 颜色不匹配语义 |

**自检操作**：全文搜索 `fillColor=` 和 `strokeColor=` 和 `fontColor=`，逐一对比颜色参考表。不匹配的 → 记录。

### E. 组件尺寸检查

| 组件类型 | 最小尺寸公式 | 常见问题 |
|---------|-------------|---------|
| 中文按钮 | `w ≥ 文字字数 × 14 + 24` | 3 字按钮 w=48 → 应 ≥ 66 |
| 英文按钮 | `w ≥ 文字字数 × 9 + 16` | "Submit" w=50 → 应 ≥ 70 |
| 输入框（短） | w ≥ 160 | 姓名框 w=100 |
| 输入框（中） | w ≥ 240 | 邮箱框 w=180 |
| 输入框（长） | w ≥ 360 | 地址框 w=200 |
| 表格列 | w ≥ 80（单列） | 列宽 50 文字截断 |
| 菜单项 | w = 200（侧栏宽度） | 菜单项 w < 200 露出侧栏底色 |

**自检操作**：提取所有按钮 `mxGeometry` + `value`，用公式计算最小宽度。实际 w < 计算值的 → 增加 w。

### F. 信息密度检查

| 限制 | 超出处理 |
|------|---------|
| 表格数据行 ≤ 8 | 截断，最后一行显示「…」或标注行数 |
| 侧栏菜单项 ≤ 10 | 截断，最后一项标注「更多…」 |
| 统计卡片 ≤ 4 | 截断，标注卡片数 |
| 表单字段 ≤ 12 | 超出部分折叠或分步 |

### G. 区域边界检查

对每个组件验证：`x ≥ cardX + 24` 且 `x + w ≤ cardX + cardW - 24`。

越界的 → 优先缩小组件 w。若无法缩小（最小尺寸不足），则增大卡片 w。

## 第六步 通道二：需求覆盖审查

对照用户提供的界面功能描述（或 PRD 功能点），逐项检查原型是否体现：

| 审查维度 | 检查要点 | 检查方法 | 常见遗漏 |
|---------|---------|---------|---------|
| **功能描述** | 页面核心能力是否在布局中有对应区域 | 搜索需求关键词是否出现在 XML `value` 中 | 只有壳子、无业务核心区 |
| **处理流程** | 主路径、分支、异常是否在界面态中可见 | 检查 `<diagram>` 标签页数是否 ≥ 主状态数 | 只有 happy path |
| **页面展现信息** | 字段/列表/卡片是否与需求表格一致 | 逐字段核对 JSON 的 `components` 数组 | 缺字段、缺状态标签 |
| **用户输入动作** | 每个操作是否有明确入口（按钮/链接/输入） | 检查需求中每个「点击/选择/输入」是否有对应组件 | 能力写了但无入口 |
| **页面响应** | 触发后的 UI 变化是否有单独状态页或示意 | 检查是否缺少「加载中」「成功」「失败」标签页 | 无加载态、无成功/失败反馈 |
| **TIP/约束** | 备注中的业务规则是否体现在 UI | 搜索需求中的「注意/必须/不能/仅」等约束词 | 权限、校验、默认值 |

**输出**：列出「已覆盖 / 部分覆盖 / 未覆盖」清单，未覆盖项标注 P0/P1。**每条标注关联的组件 id 或建议新增的组件位置**。

## 第六步 通道三：交互状态完整性

除主界面外，根据页面类型判断是否需要补充状态标签页：

| 页面类型 | 建议最少状态页 | 必补状态（优先级） |
|---------|--------------|------------------|
| 对话/智能体/Copilot | 空态、加载/流式、成功、追问澄清、失败重试、上下文预填（若需求有） | P0: 空态 + 加载 + 失败；P1: 追问 + 预填 |
| 列表/表格 | 空数据、加载中、有数据、筛选无结果 | P0: 空态 + 加载；P1: 筛选无结果 |
| 表单 | 初始、校验错误、提交中、提交成功 | P0: 校验错误；P1: 提交中 + 成功 |
| 详情 | 加载、正常、无权限/404 | P0: 加载 + 404 |
| 仪表盘 | 有数据、部分数据缺失 | P1: 部分缺失 |

单一 happy path 原型 **不足以交付**。最少补 2～4 个关键状态（空态 + 异常态为优先）。

## 第六步 通道四：业界设计对比

按页面类型与业界常见模式对比，记录差异及是否修订。

### 后台管理系统（Ant Design Pro）

| 模式 | 业界惯例 | 需修订信号 | 修订方案 |
|------|---------|-----------|---------|
| 布局 | 侧栏 200px + 顶栏 48px + 内容区 24px 内边距 | 内容顶到边、层次不清、内边距缺失 | 调整卡片 x=224，组件 x 在卡片内 +24 |
| 列表页 | 筛选区（搜索+筛选项） + 工具栏（新建/导出等按钮） + 表格 + 分页右对齐 | 缺筛选区、缺分页、操作按钮在表格下方而非上方 | 新增搜索栏行；分页移至表格右下；操作按钮移至表格上方工具栏 |
| 表单 | 标签左对齐、必填字段红色星号、提交/取消按钮右对齐在表单底部 | 标签居中或右对齐、无必填标记、按钮居中 | 标签加红色 `*` 前缀；按钮组移至表单卡片右下 |
| 详情 | 描述列表（标签-值对）+ 操作按钮在顶部或底部 | 纯文本堆叠无格式 | 改为左右两列标签-值布局 |
| 反馈 | Message/Notification 顶部通知 + 行内状态 Tag | 仅静态文字无状态组件 | 顶栏右侧加通知图标（红点）；表格状态列用颜色 Tag |

### 对话 / Copilot 类

| 模式 | 业界惯例 | 需修订信号 | 修订方案 |
|------|---------|-----------|---------|
| 布局 | 会话列表（280px）\| 对话区 \| 上下文/引用侧栏（320px）三栏 | 单栏堆叠所有信息、无会话列表 | 拆为三栏：左栏会话列表、中栏对话、右栏上下文 |
| 输入 | 多行 Textarea（最少 3 行）+ 附件 chip + 发送按钮右下 | 单行输入框（h=32） | Textarea 改为 h≥80；加附件上传区 |
| 智能体消息 | 可折叠思考步骤 + 最终回答 + 引用来源卡片 | 仅一条文本回复、无步骤过程 | 消息卡片内加折叠区块和引用列表 |
| 操作入口 | 编辑/确认/重试等操作挂在**结果卡片/消息气泡**上 | 全局底部工具栏、操作与消息分离 | 操作按钮移至每条消息卡片内（右下或底部） |
| 异步任务 | 消息内进度条/步骤状态 + 顶栏 Toast 通知 | 无进度展示、无通知 | 消息卡片内加步骤指示器；顶栏右侧加通知中心 |
| 选择器 | Tag/Select 下拉 + @ 提及，非纯文本按钮 | 「指定XX」按钮无选项交互 | 按钮改为 Select 下拉或 Tag 多选组件 |
| 上下文 | 项目/会话信息侧栏预填 | 对话与业务上下文脱节 | 右侧栏展示当前项目、会话 ID、关键参数 |

### 审计/企业业务场景

| 模式 | 业界惯例 | 需修订信号 | 修订方案 |
|------|---------|-----------|---------|
| 可追溯 | 步骤明细列表、引用来源链接区域、操作留痕时间线 | 黑盒输出、无来源 | 结果区加「查看详情」折叠面板；底部加操作日志时间线 |
| 人机协同 | 人工确认/驳回/编辑入口显著（主色按钮，非灰色小字） | 仅展示 AI 结果、无可操作入口 | 卡片底部加确认/驳回按钮组（主色+次色） |
| 项目上下文 | 顶栏或侧栏展示项目/单位/角色上下文条 | 对话界面与业务系统完全脱节 | 顶栏下方加上下文条（项目名 + 切换入口） |

### 对比操作流程

1. **匹配页面类型** → 选择上表对应分类
2. **逐维度对比** → 当前原型 vs 「业界惯例」列
3. **判定差异性质**：
   - 需求有特殊说明 → 合理差异，记录不修订
   - 需求未提及但业界通用 → 默认按修订方案执行
   - 需求明确与此相悖 → 以需求为准，记录跳过原因
4. **输出差异表** → 维度 / 业界 / 当前 / 修订（是/否）/ 修订方案

## 第六步 通道五：修订优先级

| 优先级 | 标准 | 处理 |
|--------|------|------|
| **P0** | 需求明确写出但未体现；主路径不可用；与 PRD 处理流程矛盾；组件坐标严重错位致无法辨认 | **必须修订** |
| **P1** | 业界主流模式、显著提升可评审性；关键异常/空态缺失；对齐/间距/字号/颜色偏差；组件尺寸不足 | **建议修订**（默认执行） |
| **P2** | 体验优化、非 MVP 阻塞 | 可选，时间允许则做，在摘要中提及 |

## 第六步 通道六：执行修订

1. **汇总修订清单**：合并通道一至四的 P0/P1 问题，去重
2. **更新 JSON 描述**：先改 JSON（`components`、`states`、`pages`、坐标），确保设计文档与实际一致
3. **修改 drawio XML**：按清单逐项修改 `<mxGeometry>` 和 `<mxCell>` style
4. **重新运行重叠检测**：`python3 /Users/zhangjr/.claude/skills/ui-to-drawio/references/check-overlap.py <file>.drawio --verbose`，直至通过（最多 3 轮）
5. **重新导出全部 PNG**：每页重导，确保与 .drawio 版本一致
6. **二次验证**：修订后再读 XML，确认通道一中发现的坐标/字号/颜色问题已修复
7. **交付 Review 摘要**

**禁止**：跳过 Review 直接交付初版；Review 发现 P0 未修却标记完成。
